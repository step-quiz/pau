# procediments/ — animated step-by-step procedures

Small pages, inside the PAU site, that show a mechanical procedure (from the *Àlgebra* block: the determinant of a 3×3 matrix with a parameter (Sarrus) and the values that make it zero, the rank of a matrix by bordering minors, a compatible indeterminate 3×3 system solved by Gauss with its solution set, the discussion of a system with a parameter (Rouché–Frobenius), the inverse of a 3×3 matrix by adjoints, matrix equations, and the echelon form of a 3×4 matrix by Gauss; from the *Probabilitat* block: probability trees and the law of total probability, Bayes' theorem, and the binomial distribution; from the *Anàlisi* block: the equation of the tangent line, relative maxima and minima, the growth/decrease table, six optimisation problems, six cubics determined from conditions, Bolzano's theorem with bisection, the asymptotes of a rational function, and integrals: a primitive with a condition, Barrow's rule, the area between a curve and the x axis, the area between two curves, a parameter from an integral or an area; from the *Geometria* block: the equation of a plane, a line given by two planes, the relative position of a line and a plane and of two lines, distances, projections and symmetric points, triangle area and tetrahedron volume, and the common perpendicular) as an animation in the style of Graspable Math. The student watches symbols move, merge and change, one step at a time, with a short explanation for each step. The data (the function, the point…) can be changed with arrows or through the address.

**Reusing the engine for another subject (ESO, physics, chemistry, syntax…)? Read `graspable-formulae.md`.** **New session? Read `INSIGHTS.md` first** (design rationale, lessons learned, and a playbook for change requests). This file is the reference.

Principles: keep it simple, step by step, smooth, and **every line shown is a true equality** (checked automatically, see §7).

Student-facing text is Catalan; code comments are Catalan; this file is English.

### Address format (recta tangent)

`recta-tangent.html?f=2x^2-3x+1&x0=2`

- For `creixement.html`, `f` may also be a quotient: `1/x`, `2x/(x+1)`, `(x^2+3)/(x-1)` (numerator and denominator with more than one term go in parentheses). It is rejected, with the reason, if the denominator is a number other than 1, if numerator and denominator share a factor, or if the domain or the critical points are irrational.
- `f` is written as a student would write it: `x^3-3x+1`, `x(x-5)`, `(x-1)^3`, `2x²−3x+1`, `0,5x`… It must be a polynomial of degree ≤ 3 with integer coefficients between −9 and 9 that depends on x. `x0` is an integer between −5 and 5. A missing parameter takes its default.
- The engine reads the query string itself: a literal `+` means plus (with `URLSearchParams` it would become a space). `%2B` also works. When it writes the address, `+`, `^`, `/` and `,` stay literal (`?f=x^3+1`, `?p=0,25`).
- If the address is wrong, the page explains why (in Catalan) and shows the default example.
- When the student changes the data, the address is rewritten with `history.replaceState`, so it can be copied and shared.

## 4. Steps and keys

`passos(v)` returns an array of frozen steps:

```js
{
  files: ['TeX of row 0', 'TeX of row 1'],     // '' = empty row
  classes: ['', ''],                           // CSS class per row ('final' = highlighted answer)
  text: 'Explanation with $TeX$.',
  cursor:    {clic: 'k'} | {arrossega: 'k', fins: 'k2'},   // optional
  reanomena: {newKey: 'oldKey'},               // optional
  fusiona:   {newKey: ['oldKey', …]},          // optional
}
```

A row may also be **text** instead of TeX (e.g. a problem statement): `Formules.filaText(text)` (a string starting with `§`). The text may contain `$TeX$` and phrases `Formules.frase(key, text, mark)` (written `{{key|mark|text}}`): a keyed phrase moves, merges and can be dragged like a symbol; `mark` (`objectiu` and `avis` yellow, `condicio` green, `doble` green with a «×2» badge) highlights it (CSS `.marca-…`). `Formules.enunciatMarcat(text, mark)` turns a statement with `[id:phrase]` / `[id*:phrase]` into a text row: phrases get keys `E<id>1`, `E<id>2`…, `mark(id)` gives their current mark, and it returns the key of each id's main phrase (starred, or the first). Text rows wrap, keep a fixed text size and are left out of the board-width fit. A change of mark counts as a change (anticipation box and cross-fade), because the engine compares `className` too.

Build it with `Formules.guio(nFiles)`: set `g.files[i]` / `g.classes[i]`, call `g.afegeix(text, options)`, return `g.passos`. A step identical to the previous one (same TeX, same classes) is skipped, so optional steps («Calcula cada terme») need no special case. `g.completa(text)` appends a sentence to the last step when the board must not change (e.g. «l'equació no té solucions»).

### Keys

Every symbol that must be followed from one step to the next is written as `\htmlData{k=<key>}{<symbol>}` (helpers `Formules.clau`, `op` for binary operators, `rel` for `=`). A key matches `/^[A-Za-z][A-Za-z0-9]*$/` and is unique within a step (all rows together). `clau(k, tex, marca)` adds a mark, `\htmlData{k=<key>,marca=mes}{…}` (`mes`, `menys`, `tria`), drawn as a coloured background (e.g. the three entries of a Sarrus product).

Long rows: `Formules.enLinies(inici, peces, {ample = 300})` puts the pieces (each with its own sign) on as many lines as needed so that none is wider than `ample` px on a phone (`ampleTex` estimates the width of a TeX string; calibrated with KaTeX); with one line it returns plain TeX, otherwise an `array`.

Polynomial helpers use a one-letter prefix `P` and the degree `n` of the term:

| Key | Symbol | Key | Symbol |
|---|---|---|---|
| `Psn` | sign | `Pcn` | coefficient (absolute value) |
| `Pvn` | x, or the value that replaces it | `Pen` | exponent |
| `Pmn` | multiplication dot | `Ptn` | value of a computed term |
| `PR` | value of the whole expression | `PA`, `PB`, `PQ` | `(`, `)` and `'` of `(…)'` |
| `PEn` | new exponent when deriving | | |

`membreEsquerre(L, …)` writes `f(x) =` with prefix `L`: `LF` name, `LP` prime, `La`/`Lb` parentheses, `LX` argument, `Lq` `=`. Use different letters for `L` and `P`. The tangent equation (row 0) uses keys `T…`, documented at the top of `recta-tangent.js`.

### 4.1 Solving «polynomial = 0»

`Formules.resolPolinomi(g, row, P, terms, firstText, firstOptions)` adds the steps that solve `terms = 0` (degree ≤ 2, integer coefficients, rational roots) on one row, the way it is taught: divide by a common factor (and make the leading coefficient positive); degree 1: move the constant, divide; `Ax² + Bx = 0`: take out `x`, split the product, solve the linear factor; `Ax² + C = 0`: `x² = k`, `x = ±√k`; otherwise the quadratic formula (substituted, discriminant, square root, split `±`). No real solution: the last caption says why. It returns the solutions in ascending order as `[{valor, clau}]`, where `clau` is the key of the number on the last row (to drag it elsewhere). `Mates.arrelsRacionals(terms)` tells beforehand whether the roots are rational (procedures reject irrational cases in `valida`).

`Formules.resolEquacio(g, {fila, treball, P, termes, text, X, davant, opcions, lila, final, serveix})` is the one every page uses (David's conventions, Oct 2026): the equation (and its simplified form, if divided) stays on `fila`, and every other step goes to the working row `treball` (a frozen copy with `Y…` keys stays above while the original symbols move down); with `lila`, a last step marks the solutions in lilac (`final`: its caption, a text or a function of the solutions; default «Les solucions són …») and crosses out in red the ones for which `serveix(valor)` is false (outside the domain…). Pages write the bare named equation first («f'(x) = 0», «A'(x) = 0», «f(x) = 0», «|A| = 0») and then substitute. It returns `[{valor, clau, fila}]`.

### 4.2 Compact keyed notation: `Formules.marcat`

Long scripts written as data (e.g. solving a system) use `marcat(text)`: `⟦k:tex⟧` is the symbol `tex` with key `k`. If the text starts with `prefix: `, every key gets the prefix and the single bare `=` (outside `⟦…⟧`) gets the key `prefix + 'q'`. Contents `=`, `<`, `>` are written as relations (`rel`) and `+`, `-`, `\cdot` as operators (`op`). Example: `marcat('q4: ⟦a:a⟧ + ⟦b:(-3a)⟧ = ⟦r:-2⟧')` has keys `q4a`, `q4b`, `q4q`, `q4r`. It throws on unbalanced brackets, invalid keys or more than one bare `=`.

In `polinomi-condicions.js` each equation of the system keeps its prefix (`q1`…`q4` from the translation; `q5`, `q6`… for the new equations of the solving phase), so an equation moves from the work row to the system just by keeping its keys, and an in-place change of one term (`⟦c:c⟧` → `⟦c:0⟧`) morphs only that term.

### Transition semantics (`motor.js`, `creaPissarra`)

From step A to step B:

1. **Same key** in A and B (or `reanomena: {new: old}`): the same symbol. It moves to its new place (and size); if its content changes, the old one cross-fades into the new one.
2. **`fusiona: {new: [old…]}`**: the old symbols fly into the new one, which pops in.
3. Other old symbols fade out; other new symbols fade in. Unkeyed parts of the rows cross-fade.
4. **Cursor**: `{clic: k}` clicks the old symbol `k` before anything moves; `{arrossega: k, fins: k2}` grabs `k` and drags it to the new symbol `k2` (default: its pair or fusion target), with a box that follows it.
5. **Anticipation boxes**: in steps without a drag, light-blue boxes first mark every symbol that will change or vanish (symbols merging into the same target share one box), then follow them to their new place. Steps with boxes last longer (`TEMPS.pasAmbAvis`).
6. **Wrapped symbols**: a keyed phrase of a text row may span several lines (its `getClientRects()` has more than one fragment, typically on phones). A single-line ghost of it would be drawn at the paragraph's left edge, over other text, so a wrapped symbol (in A or in B) gets no ghost: it stays visible in its own layer (class `sense-fantasma`) and cross-fades with it. Its anticipation boxes are drawn per line fragment, and the cursor clicks or grabs its first fragment. Ghosts carry `data-de=<key>` (useful in browser tests).

Positions are measured on the real KaTeX output, so any TeX layout works. Rules that keep the animation meaningful (all checked by the tests): a renamed new key is not in A and its old key is not in B; a fusion source is in A and not in B and merges only once; cursor keys exist (`clic`, `arrossega` in A; `fins` in B); the first step animates nothing.

## 5. Engine features

- Player: restart, previous, play/pause, next; one dot per step (jump); speed (slow/normal/fast); keyboard Space (play/pause, except on a focused button), ← and →.
- Board font: largest size (30 px, 22 px on phones) at which the longest line of the whole procedure fits; on large screens also small enough (down to 18 px, `MIDA.minimaAlcada`) for the tallest step, the player and the step text to fit in the window below the header and the statement (otherwise the controls stay stuck at the bottom); refitted when the width changes or the fonts finish loading.
- Editor: ↑/↓ under each number, hold to repeat (stops at the limit); `valida` messages; regenerates the steps 350 ms after the last change and rewrites the address.
- `prefers-reduced-motion`: every duration × 0.35.
- Accessibility: buttons have Catalan labels; the step text is an `aria-live` region; KaTeX also outputs MathML; editor values are `spinbutton`s (arrow keys).
